### 5.5 인용의 한계

- 정답 인용은 항상 한 섹션인데, 같은 문장이 여러 섹션에 들어 있습니다. 정답은 학습자가 보고 있는 페이지인데, 요청에 직접 들어 있지 않아 이전 대화로 짐작할 수밖에 없습니다.
- 검색 1위 정확도는 조정용과 평가용 모두 약 0.90입니다. LLM 재순위와 질의 변형으로 넘지 못했습니다.
- 인용을 2개 내면 정답이어도 F1이 깎이고, 1개만 내면 1위가 틀린 약 10%를 구하지 못합니다. 실측에서 두 효과가 거의 상쇄되었고, 평가용에서는 1개가 손해였습니다.

### 5.6 자료 유무 판단의 한계

- 튜터 out_of_material은 10건 중 6~8건을 맞힙니다. 어려운 문항은 자료에 비슷한 주제는 있는데 묻는 구체적인 기준만 없는 경우입니다.
- 기준을 어느 쪽으로 옮겨도 다른 쪽이 나빠집니다. "답했으면 자료가 있다"는 규칙은 처리율을 0.8에서 0.6으로 떨어뜨렸고, 별도 판정 호출은 생성기와 정확도가 비슷했습니다.

### 5.7 생성의 한계

- gpt-5-nano는 자료를 정확히 복사하지만 틀린 실습이나 사례의 문장을 복사하기도 합니다. 원문 인용 자체는 맞으므로 인용문 검증으로 잡히지 않습니다.
- 출력을 늘리는 방법은 부하에서 비쌉니다. 근거 문장을 먼저 뽑는 방식은 조정용에서는 괜찮아 보였지만 동시 64에서 대체 응답과 형식 오류가 나왔습니다.
- 자료 원문 덧붙이기는 지표상 이득이지만 대가가 있습니다.
  - 검색 1위가 틀린 약 10% 문항에서는 다른 섹션의 문장이 붙습니다.
  - 답변이 길어지고 내용이 겹칠 수 있어 학습자 경험에는 손해일 수 있습니다.
  - 1회 판정이지만 충실성이 0.936에서 0.894로 내려간 회차가 있습니다.

### 5.8 지연과 부하

| 실행 | 튜터 p50 / p95 / 최대 | 가드 p50 / p95 / 최대 | 실행 시간 |
|---|---|---|---|
| `b394ab8` | p95 12.9초, 최대 14.4초 | p95 8.8초, 최대 11.6초 | 66.9초 |
| `fffa96c` | 10.5 / 19.7 / 22.5초 | 9.1 / 17.3 / 20.8초 | 66.8초 |
| `7d44c16` | 10.5 / 22.9 / 24.8초 | 7.9 / 15.6 / 20.1초 | 86.3초 |

- 튜터 최대 지연이 요청 마감 25초에 닿았습니다. 호출 수는 거의 같은데 느려져 운영진 프록시 혼잡으로 보이며, 이 부분은 서버 코드로 통제할 수 없습니다.
- 평가용 200건에 LLM·임베딩 호출이 약 800회이니 요청당 약 4회입니다. 공식 600건이면 약 2,400회로 추정됩니다. 규격은 과한 호출을 어뷰징으로 볼 수 있다고 하지만 기준을 공개하지 않아, 이 수준이 안전한지 판단할 수 없습니다.
- 다수결과 배심원은 안정성을 지연과 호출 수로 산 것입니다. 추가 호출을 더 쌓을 여유는 작습니다.

### 5.9 대회 조건이 정한 한계

- 채팅 모델은 gpt-5-nano로 고정입니다.
- 미리 학습된 임베딩, 리랭커, 분류 모델을 쓸 수 없습니다. 공개 문항으로 직접 학습한 분류기는 허용되지만 400건으로는 LLM에 크게 못 미쳤습니다.
- 요청에 과목과 근거 정보가 없고 요청 사이 상태도 쓸 수 없어, 학습자가 보는 페이지를 직접 알 방법이 없습니다. 인용 문제의 가장 직접적인 해결책이 막혀 있는 셈입니다.
