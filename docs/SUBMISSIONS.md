# 공식 제출 기록

공식 점수와 서버 상태를 같은 표에 남겨, 점수가 흔들린 이유가 문항 표본인지 서버 쪽 실패인지 가립니다.

## 제출할 때

1. 서버 출력을 파일로 남기며 8000 서버를 띄웁니다. 로그에는 시각, 상태, 지연, 길이, 오류 종류만 있습니다.

   ```bash
   mkdir -p logs
   set -a; . ./.env; set +a
   python3 -m uvicorn server:app --host 0.0.0.0 --port 8000 2>&1 | tee -a logs/8000.log
   ```

2. 제출하고 채점이 끝날 때까지 기다립니다. **채점 중에는 서버, 코드, 로그를 건드리지 않습니다.**
3. 채점이 끝나면 표에 넣을 행을 뽑습니다.

   ```bash
   python3 eval/log_summary.py logs/8000.log --last-run --row
   ```

4. 뽑은 행의 `?` 칸을 결과 메시지의 값과 커밋 해시로 채웁니다. 토큰은 적지 않습니다.

`--row`를 빼면 호출 종류별 수와 로그 감사 결과까지 한 줄로 나옵니다. 감사 항목의 허용 밖 줄이나 필드가 0이 아니면 그 제출의 로그를 공유하지 말고 원인을 먼저 확인합니다.

## 칸 설명

- **대체 응답:** 마감 / 생성 실패 / 판정 실패 / 그 외의 요청 수입니다.
  - 마감: 요청 전체 마감에 걸렸거나 생성 호출이 시간 안에 끝나지 않은 경우
  - 생성 실패: 생성 호출이 시간 안에 끝났지만 쓸 수 있는 답을 못 받은 경우
  - 판정 실패: 입력 판정, 근거 판정, 자료 확인 중 하나가 실패해 기본값을 쓴 경우
  - 그 외: 라우트 예외, 요청 검증 실패
- **API 오류:** 상태가 `error`인 LLM·임베딩 호출 수입니다. 재시도로 복구된 호출과, 3초를 넘겨 글자 검색만으로 처리한 질의 임베딩도 포함합니다.
- **지연:** p50 / p95 / 최대, 초 단위입니다.
- **호출 수:** 취소된 호출과 재시도를 포함한 LLM·임베딩 호출 수입니다.
